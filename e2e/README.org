#+TITLE: e2e: Playwright journeys

The journeys drive goob-toob through Chromium, Firefox and WebKit
(Playwright's own builds) and judge it by metrics: drift, seeks, stalls,
rates, time to sync. Specs, config and global setup are ClojureScript
under =src/=, compiled by the =:e2e= shadow-cljs build into =out/=.
Every number a spec asserts against lives in
=src/goob_toob/e2e/thresholds.cljs=.

* Run everything
From the repo root, with podman installed:
#+begin_src sh
make e2e-image
make e2e
#+end_src
=make e2e-image= builds =localhost/goob-toob:latest-e2e= (Playwright's
image plus Java 21, Clojure and ffmpeg); the first build pulls about
2 GB. =make e2e= builds the client and the specs inside that image,
starts the server on port 18080 with a fresh storage dir, renders and
uploads the test clips, and runs every journey in all five projects.
The run ends with Playwright's summary line, for example
=36 passed (12.0m)=.

* Run one engine, or one journey
=E2E_ARGS= goes straight to =playwright test=. Quote patterns with single
quotes; the Makefile wraps the command in double quotes.
#+begin_src sh
make e2e E2E_ARGS=--project=firefox
make e2e E2E_ARGS="-g laggard"
make e2e E2E_ARGS="--project=webkit -g 'late joiner|dropped'"
#+end_src
The projects are =chromium= and =firefox= (strict autoplay: a start
with sound needs the document to have been touched; =chromium= uses
=--autoplay-policy=document-user-activation-required=, Chrome's shipped
policy, because =user-gesture-required= also refuses a play more than
5 s after the touch), =chromium-lenient= and
=firefox-lenient= (any start allowed) and =webkit= (Playwright cannot
force its policy; the autoplay journeys record its outcome). CI runs
=chromium= and =chromium-lenient=. =firefox=, =firefox-lenient= and
=webkit= stay available locally for DOM and gesture checks; their decode
timing on shared runners said nothing useful (see issue #42).

Playwright's =evaluate= (and so =waitForFunction=, locators and trace
DOM snapshots) runs with a user gesture in all three engines, which
gives the page sticky activation and lets it start with sound under the
strict policy. Journeys that assert an autostart's outcome open the
viewer with =:hands-off? true= and watch its socket frames and clientlog
requests (=party/wait-seen!=) until the outcome is logged; the config
keeps traces without DOM snapshots for the same reason.
CI does not build the image per run: the =e2e-image= job pushes it to
=ghcr.io/soniccyclone/goob-toob-e2e:<hash of its inputs>= once per change
to the Containerfile or the lock files, and the legs run inside it. To
use that image locally instead of building: =E2E_IMAGE=ghcr.io/soniccyclone/goob-toob-e2e:<tag> make e2e=
after =podman login ghcr.io=.

* Read the metrics
Every journey records before it asserts, so a failing run still writes
its numbers.
- =metrics/summary.md=: one row per engine and journey (drift p95, max
  and final, rate bounds, seek, stall and seek-back counts, plus the
  journey's own numbers in the last column).
- =metrics/<engine>-<spec>-<journey>.json=: the full sampled series and
  the summary.
#+begin_src sh
cat e2e/metrics/summary.md
#+end_src

* Look at a failure
A failed journey keeps its trace and video under =test-results/=; the
HTML report is in =report/=. Open them from the repo root with the
image's Playwright, which serves the viewer on port 9323:
#+begin_src sh
podman run --rm --ipc=host -p 9323:9323 -v "$PWD":/app:z -w /app/e2e localhost/goob-toob:latest-e2e \
  npx playwright show-report report --host 0.0.0.0
#+end_src
then browse to http://localhost:9323 and open the trace from the failed
test. A single trace opens the same way with
=npx playwright show-trace --host 0.0.0.0 --port 9323 test-results/<dir>/trace.zip=.

* Expected failures and runtime skips
- =a laggard catches up without seeking= skips itself at runtime (issue
  #42) only when the element reports =MEDIA_ERR_DECODE= after the
  injected 3.5 s backward seek, which Playwright's WebKit build does in
  some environments ("Failed to send data for decoding"; the element
  never plays again). It records its metrics with =decode-error=true=
  first, then reports as skipped. Without the decode error it asserts
  normally in every engine.
