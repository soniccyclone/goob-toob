* Goal
A room stops being "one video" and becomes an ordered queue of the host's
uploaded videos with a current item. The host builds and edits the queue
from the admin console, including while the party is running. When the
room's clock passes the end of the current video the server moves everyone
to the next one and keeps playing; the host or a co-host can skip ahead,
go back or jump to any item from the watch page. Viewers see the queue and
what is up next. Late joiners land on the right video. Existing rooms
migrate to one-item queues and keep their links.

Depends on the test-lockdown plan (tests, fixture, =start-action=) and the
autoplay plan (=autostart!= / =settle!=, which the item switch reuses so a
viewer who already pressed play follows into the next video without
touching anything). The Playwright journeys plan is where the item switch,
auto-advance and end-of-queue get their browser tests.

* Decisions
Each with the evidence; Nathan flips what he disagrees with before
approval.
- *The room is the playlist.* No separate playlists table or CRUD. The ask
  is "build up a playlist of the videos they have uploaded" for a room;
  reusable named playlists would add a screen and an entity nobody asked
  for. If that need appears, =room_items= copies cleanly into
  =playlist_items= later.
- *=rooms.video_id= becomes "the current video".* It already exists, is
  =NOT NULL=, and ~sync.clj:20~ already loads it into the live room. SQLite
  cannot =DROP COLUMN= a column that carries a =REFERENCES= clause, so
  keeping it as the current pointer avoids a table rebuild. Consequence: a
  room always has a current video, so a queue is never empty; the last item
  cannot be removed (close the room instead).
- *No duplicate videos in a queue.* =PRIMARY KEY (room_id, video_id)=. It
  lets the video id identify an item, so the wire protocol and the jump
  command carry =video-id=, not an item id. Binge-watching the same episode
  twice is not a use case.
- *Foreign keys go on for real.* The lockdown audit found every connection
  runs with =foreign_keys=0= (the PRAGMA is per connection; next.jdbc opens
  one per =execute!=). This plan touches the schema, so it also sets the
  pragma through the driver property on every connection and runs
  migrations with it off, as the SQLite docs prescribe for schema changes.
  Existing manual guards stay.
- *Deleting a video that sits in a queue is refused* (409 naming the
  rooms). Today the video's rooms are silently closed
  (~repos/video.clj:62~). With queues, silently editing a running party's
  list from the library page is worse than a clear error. The admin removes
  it from the queue (or closes the room) first.
- *The current item cannot be removed from the queue* (409). Skip first.
  Keeps the in-memory room and the DB pointer from disagreeing mid-edit.
- *Skipping is playback control.* =next=, =prev=, =jump= travel over the
  websocket as =cmd= ops and obey the same gate as play/pause/seek
  (~ws.clj:29-30~): host, or anyone when "co-hosts can drive" is on. Queue
  *editing* is admin-only HTTP.
- *A skip or an auto-advance always starts the next item playing at 0.*
  Netflix behaviour. The host pauses if they want a break. End of queue:
  the room pauses at the end of the last video and says so.
- *Auto-advance is server-side, from the room clock.* The server knows
  =duration= (videos table) and the authoritative position; it does not
  wait for clients to report =ended= (they lag, stall or lie). A laggard 3 s
  behind gets cut off 3 s early; accepted.
- *Position within the current video stays in memory only*, as today; the
  current item persists. A restart lands everyone at 0 of the current
  video, paused, instead of 0 of the first video.
- *Rooms get a title.* Nullable =rooms.title=, defaulting to the first
  video's title at creation, editable from the admin row. The lobby card
  otherwise reads "S01E01" while the party is on E05.

** Migration ~resources/migrations/003-room-items.sql~
#+begin_src sql
ALTER TABLE rooms ADD COLUMN title TEXT;
CREATE TABLE IF NOT EXISTS room_items (
  room_id  TEXT NOT NULL REFERENCES rooms(id) ON DELETE CASCADE,
  video_id TEXT NOT NULL REFERENCES videos(id) ON DELETE CASCADE,
  position INTEGER NOT NULL,
  PRIMARY KEY (room_id, video_id)

  SELECT id, video_id, 0 FROM rooms;
#+end_src
The =DELETE= clears any orphan rows that the FK-off era let through, so the
=foreign_key_check= below passes on old databases. Add the file name to
=db/migrations=.

** ~db.clj~: foreign keys on every connection, off during migrations
- =init!=: datasource spec becomes ={:dbtype "sqlite" :dbname db-path :foreign_keys true}=.
  next.jdbc forwards unknown keys as driver properties; sqlite-jdbc reads
  =foreign_keys= as the pragma. Drop the standalone =PRAGMA foreign_keys=ON=.
- =migrate!= takes one connection for its whole run:
  #+begin_src clojure
  (with-open [conn (jdbc/get-connection db)]
    (jdbc/execute! conn ["PRAGMA foreign_keys=OFF"])
    (doseq [name migrations :when (not (applied name))]
      ... (jdbc/with-transaction [tx conn] ...) ...)
    (when-let [bad (seq (jdbc/execute! conn ["PRAGMA foreign_key_check"]))]
      (throw (ex-info "foreign key violations after migration" {:rows bad}))))
  #+end_src
  Fail fast: a violation here is a bug in a migration, not a condition to
  limp through.

** Shape of a queue on the wire
#+begin_src clojure
;; one item
{:video-id "..." :title "S01E02" :duration 1321.4 :status "ready" :position 1}
;; welcome gains
{:queue [item ...] :video-id "<current>"}
;; state and beat gain
{:video-id "<current>"}
;; new state op, broadcast on every item change
{:type "state" :op "item" :video {:id :title :duration :dash} :video-id id
 :pos 0.0 :t0 now :playing true :rate 1.0 :now now :ended false}
;; end of queue: a pause with a flag
{:type "state" :op "pause" :pos <duration> ... :ended true}
;; queue edited (admin HTTP) → room broadcast
{:type "queue" :queue [item ...] :video-id "<current>"}
#+end_src

** ~sync_core.cljc~ (pure)
#+begin_src clojure
(defn neighbour
  "ids is the queue's video ids in order. Returns the id after (:next) or
  before (:prev) current, nil at either end or if current is not queued."
  [ids current dir]
  (let [i (.indexOf (vec ids) current)]
    (when (<= 0 i)
      (get (vec ids) (case dir :next (inc i) :prev (dec i))))))

(defn ended?
  "A playing room whose clock has reached the current video's duration."
  [{:keys [playing? duration] :as room} now]
  (boolean (and playing? duration (>= (expected-pos (assoc room :now now)) duration))))
#+end_src

** ~services/sync.clj~
- Live room gains =:duration= (from the video row) and keeps =:video-id=.
  =room-for= reads both via =videos/get-by-id=.
- =state-msg= adds =:video-id=.
- New:
  #+begin_src clojure
  (defn- video-descriptor [v]
    {:id (:id v) :title (:title v) :duration (:duration v)
     :dash (str "/dash/" (:id v) "/manifest.mpd")})

  (defn set-item!
    "Move the room to video-id (must be queued), position 0, playing.
    Persists the pointer, broadcasts the item state."
    [room-id video-id]
    (let [v (videos/get-by-id video-id)
          now (mono-ms)]
      (rooms/set-current! room-id video-id)
      (swap! rooms* update room-id assoc :video-id video-id :duration (:duration v)
             :pos 0.0 :t0 now :playing? true :rate 1.0)
      (log/info "room" room-id "item" (:title v))
      (broadcast room-id (assoc (state-msg (get @rooms* room-id))
                                :op "item" :video (video-descriptor v) :ended false))))

  (defn end-queue! [room-id]
    (let [now (mono-ms)]
      (swap! rooms* update room-id #(assoc % :pos (double (or (:duration %) 0)) :t0 now
                                            :playing? false :rate 1.0))
      (log/info "room" room-id "reached the end of the queue")
      (broadcast room-id (assoc (state-msg (get @rooms* room-id)) :op "pause" :ended true))))

  (defn item-cmd! [room-id op video-id nick]
    (log/info "room" room-id op (or video-id "-") "by" nick)
    (let [ids (map :video-id (rooms/queue room-id))
          cur (get-in @rooms* [room-id :video-id])
          target (case op
                   "next" (sc/neighbour ids cur :next)
                   "prev" (sc/neighbour ids cur :prev)
                   "jump" (some #{video-id} ids)
                   nil)]
      (if target (set-item! room-id target) (when (= op "next") (end-queue! room-id)))))

  (defn queue-changed! [room-id]
    (when (get @rooms* room-id)
      (broadcast room-id {:type "queue" :queue (rooms/queue room-id)
                          :video-id (get-in @rooms* [room-id :video-id])})))
  #+end_src
- =tick-room!=: first thing, =(when (sc/ended? room now) ...)=: if
  =neighbour :next= exists → =set-item!=, else =end-queue!=; then return
  (the item broadcast is this tick's message; the beat resumes next tick).
- =host-cmd!= unchanged. =prev= at the first item is a no-op (not a
  restart; =seek 0= does that).

* Risks and open questions
- *FK on for real is the riskiest line in the plan.* It could reject writes
  that silently succeeded before. Mitigations: migration 003 deletes
  orphan rooms; =foreign_key_check= fails loudly at startup; the manual
  guards in =create!= and the 409 on video delete remain. If an existing
  install hits a violation 003 does not cover, startup fails with the rows
  in the log, which is the intended behaviour (fix the data, not hide it).
  Verify the =:foreign_keys true= property path with the db test before
  anything else; if next.jdbc does not forward it, fall back to
  =(jdbc/get-datasource {... :dbname (str path "?foreign_keys=on")})= or a
  =SQLiteDataSource= with =setEnforceForeignKeys=.
- *A missed =item= broadcast.* A viewer in a reconnect blip gets a fresh
  =welcome= (handled) and every beat carries =:video-id= (handled by the
  mismatch check). Two belts.
- *attachSource and the element.* dash.js resets its controllers and the
  element's source; =currentTime= resets to 0 and =duration= changes.
  The seek slider's =max= follows =video.duration= on its 1 s tick. The
  quality cap resets. If a browser leaves the old frame visible until the
  new stream's first segment, that is a sub-second flash; accepted.
- *Auto-advance cuts laggards.* The clock passing =duration= moves
  everyone. A viewer 3 s behind loses 3 s of credits. The alternative
  (wait for the slowest) holds the whole room for a stalled tab. Decided:
  clock wins.
- *Duration drift.* ffprobe's =format.duration= and the DASH presentation
  duration differ by up to a segment's rounding. Advance fires at the
  probe value; the element may have reached =ended= a fraction earlier
  (last frame held, harmless) or have a fraction left (cut, harmless).
- *Admin UI size.* The queue editor is the largest client change. Plain
  DOM as the rest of =admin.cljs=; no state beyond re-rendering a row from
  the response. If it balloons, split a =queue-editor= fn into its own
  ns.
- *Co-host skipping.* Anyone with the link can skip when "co-hosts can
  drive" is on. Same trust level as pausing the room; the checkbox is the
  control.
- *Deleting a video in a queue is now refused.* Behaviour change on the
  library page; the toast explains. Nathan may prefer the old silent
  close; it is one branch to flip.
