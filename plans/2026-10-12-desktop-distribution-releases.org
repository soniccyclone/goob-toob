* Goal
Turn goob-toob into a double-click desktop app for Windows (primary audience)
and Linux. An Electron shell owns the Clojure server, a *vendored cloudflared*
gives the admin a public URL to toss at friends with zero setup, the admin
password disappears for desktop mode (loopback-only admin port instead), the
storage folder is picked *in-app*, and builds.sr.ht produces the installers,
published to srht.site and linked from the repo front page.

* Findings
- Boot today: =clojure -M:dev -m goob-toob.core= (~container/Containerfile:26~);
  =config/load!= *requires* =STORAGE_DIR= and =ADMIN_PASSWORD=
  (~src/clj/goob_toob/config.clj:29-34~); one Jetty on one port
  (~src/clj/goob_toob/core.clj:14-19~).
- Router: all admin API lives under one =/api/admin= subtree behind
  =require-admin= (~src/clj/goob_toob/routes.clj:196-204~); WS host status is
  the session cookie (~src/clj/goob_toob/ws.clj:44~). The admin SPA already
  asks =/api/admin/me= to decide login-vs-console (~src/cljs/goob_toob/admin.cljs~).
- ffmpeg is called as bare =ffmpeg= with a Linux-only =nice -n 10= prefix
  (~src/clj/goob_toob/services/transcode.clj:54~) — no configurable path,
  breaks on Windows.
- No uberjar task exists (~deps.edn~ has no =:build= alias).
- CI today (~.build.yml~): alpine → plans site → =hut pages publish= to
  =nathanb.srht.site/goob-toob-plans=. srht.site limit: *1 GiB per site*
  (tarball after decompression), no per-file cap — installers fit if we keep
  only the latest per platform.
- git.sr.ht has no release files; builds.sr.ht artifacts expire in 90 days →
  releases go to =nathanb.srht.site/goob-toob-releases/= (decided).
- builds.sr.ht runs Linux VMs only. electron-builder cross-packages Windows
  from Linux natively; *wine is needed only for the NSIS installer*
  (electron.build docs) — so the portable zip is wine-free (decided: NSIS +
  zip fallback).
- cloudflared quick tunnel: =cloudflared tunnel --url http://127.0.0.1:PORT=
  dials out (no open ports), prints an ephemeral
  =https://<random>.trycloudflare.com=, no account needed; Apache-2.0 so the
  binary is redistributable. Binaries: =cloudflared-linux-amd64=,
  =cloudflared-windows-amd64.exe= from GitHub releases.
- *Security fact that drives the auth design*: cloudflared runs on the same
  box, so loopback checks can't protect the admin API — anything on the
  tunneled port is public. Decided design: *two ports*. Public port (lobby,
  watch, dash, WS, /api/me) gets the tunnel; a second Jetty bound to
  =127.0.0.1= serves the admin API + admin SPA + an always-host WS and is
  never tunneled. Container mode keeps =ADMIN_PASSWORD= login unchanged.
- Licensing of bundled parts: Temurin JRE (GPLv2+CE, bundling is standard),
  ffmpeg static builds (GPL — separate process, ship license + source
  pointer), cloudflared (Apache-2.0), Electron (MIT). App itself is AGPL.

* Plan
** 1 · Server: desktop mode with two ports
1. ~src/clj/goob_toob/config.clj~: =ADMIN_PASSWORD= becomes optional.
   Mode = =:desktop= when unset, =:container= when set (current behavior).
   New keys: =:admin-port= (=GOOB_ADMIN_PORT=, default 8081),
   =:ffmpeg-path= (=FFMPEG_PATH=, default ="ffmpeg"=). =STORAGE_DIR= stays
   required in both modes.
2. ~src/clj/goob_toob/routes.clj~: =app= takes ={:keys [admin?]}=. When
   =admin?= is false: omit the =/api/admin= subtree, =/login=, =/logout= and
   the =/admin= SPA route. New =wrap-desktop-admin= middleware (assoc
   =:goob/admin true=) wraps the admin-port handler; =whoami= returns
   ={:admin true}= when that attribute is present.
3. ~src/clj/goob_toob/ws.clj~: =admin? = (or (:goob/admin req) session :admin)=
   — admin-port sockets are always host, public-port sockets unchanged.
4. ~src/clj/goob_toob/core.clj~: desktop mode starts two Jetty servers —
   public on =:port= (all interfaces) and admin on =:admin-port= with
   =:host "127.0.0.1"= (Jetty option). Container mode: single server, as today.
5. ~src/clj/goob_toob/services/transcode.clj~: ffmpeg binary from
   =:ffmpeg-path=; drop the =nice= prefix on Windows
   (=(.contains (System/getProperty "os.name") "Windows")=).
6. ~src/cljs/goob_toob/watch.cljs~: hide the "admin?" header link unless the
   welcome said =:is-host= (it would 404 on the public port).

** 2 · Build chain: uberjar + vendored binaries
7. ~deps.edn~: add =:build= alias (=io.github.clojure/tools.build=) +
   ~build.clj~ → =target/goob-toob.jar= uberjar.
8. ~scripts/fetch-vendor.sh~: pinned downloads into ~vendor/<platform>/~ —
   =cloudflared-linux-amd64= / =cloudflared-windows-amd64.exe= (GitHub
   release, pinned tag) and static ffmpeg (johnvansickle linux / BtbN
   win64-gpl), each sha256-checked. Makefile target =vendor=.
9. Makefile: =uberjar=, =vendor=, =desktop= (=electron-builder --dir= + run,
   local dev loop).

** 3 · Electron shell (~desktop/~)
10. ~desktop/package.json~ (electron, electron-builder, electron-store),
    ~main.js~, ~preload.js~, icon. Boot sequence:
    - read stored =storageDir=; if none → =dialog.showOpenDialog= first run.
    - spawn bundled JRE: =java -jar <res>/goob-toob.jar= with env
      =STORAGE_DIR=, =PORT= (free ephemeral), =GOOB_ADMIN_PORT= (free),
      =FFMPEG_PATH= (bundled); wait for =GET /api/admin/me= 200.
    - spawn =cloudflared tunnel --url http://127.0.0.1:<public> --no-autoupdate=;
      parse the trycloudflare URL from stderr.
    - open BrowserWindow at =http://127.0.0.1:<admin-port>/admin= (no login —
      admin port is always-admin).
    - preload exposes =window.goob= = {tunnelUrl, storageDir,
      pickStorageDir(), openWatch(token)} via contextBridge + IPC.
    - =pickStorageDir= → dialog → save config → restart server child → reload.
      Existing videos keep working (DB stores absolute paths); the new folder
      applies to new uploads. (Move-library is a follow-up.)
    - quit / window-close kills both children; single-instance lock.
11. ~src/cljs/goob_toob/admin.cljs~: a "sharing" card rendered only when
    =window.goob= exists: tunnel URL + copy button, storage folder + change
    button. Container mode never sees it.
12. electron-builder config: appId =org.goobtoob.app=; linux =AppImage=;
    win =nsis= + =zip=; =extraResources=: jar, =jre/= (Temurin per platform),
    ffmpeg, cloudflared, =THIRD-PARTY.org~ (licenses). No code signing.

** 4 · CI: ~.builds/release.yml~ (manual: =hut builds submit= after tagging)
13. fedora image (java-25, nodejs, wine, zip, unzip — matches the container).
    Tasks: uberjar + =shadow-cljs release client= → vendor downloads (both
    platforms) + Temurin JRE zips (linux + win, Adoptium API, pinned) →
    =electron-builder --linux AppImage --win nsis zip= → =artifact:= every
    installer → publish task gated on =git describe --exact-match 'v*'= :
    publishes *only* the AppImage + NSIS setup.exe (the zip duplicates the
    installer's payload; it stays a CI artifact and is published only if the
    wine/NSIS step failed) + tiny =index.html= (links + sha256sums) + tar →
    =hut pages publish -d nathanb.srht.site -s /goob-toob-releases=.
    Stable filenames (=goob-toob-setup.exe=, =goob-toob.AppImage=,
    =goob-toob-win.zip=) so README links never rot.
14. Version: =desktop/package.json= version == git tag; bump at release.

** 5 · Front page
15. ~README.md~: a *Download* section at the very top — *Windows* →
    =goob-toob-setup.exe=, *Linux* → =goob-toob.AppImage=, each a direct
    =nathanb.srht.site= link (the portable zip is linked only in releases
    where it was the published Windows build), plus the SmartScreen note
    ("More info → Run anyway") and a pointer to the podman path for server

* Risks and open questions
- *srht.site budget*: 1 GiB per site shared with the plans site. Publishing
  only the AppImage + NSIS installer (the zip would duplicate the installer's
  payload) puts the release set at ≈ 450–500 MB — comfortable headroom. The
  heavy parts (Electron runtime, JRE, ffmpeg, cloudflared) are all
  platform-specific binaries; the shared JS is ~2 MB, so a combined
  cross-platform artifact would only make every user download both
  platforms' runtimes. If the budget ever tightens, jlink-trim the JRE or
  move releases to Codeberg (links are one file).
- *wine/NSIS flakiness in CI*: the portable zip is always built, so a wine
  hiccup costs the installer, never the release.
- *Unsigned Windows exe* → SmartScreen "unknown publisher" warning; documented
  in README. Code signing certs are out of scope.
- *Quick tunnels are personal-use* per Cloudflare ToS: ephemeral URL per
  launch, no uptime promise. Right-sized for a watch party; say so in README.
- *Two-port invariant*: the public port must never gain admin routes —
  regression-tested (new CLJ test asserts 404 on =/api/admin/*= when
  =admin?= is false).
- *Full Temurin JRE bundled (~45 MB compressed)* rather than jlink-trimmed:
  robust first, jlink later as a size win.
- ffmpeg is GPL and cloudflared Apache: bundle =THIRD-PARTY.org~ with
  licenses + source pointers; AGPL app source = the repo link.
- Storage-dir change applies to new uploads only (absolute paths in DB);
  "move library" is a follow-up plan.
- Auto-update: out of scope; README says "download the latest".
- Container mode must not regress: =ADMIN_PASSWORD= set → today's single-port
  behavior, byte-for-byte.

* Implementation notes
Shipped same day. Deviations and found issues:

- =app= takes ={:keys [admin? login?]}=: =login?= is container-mode only.
  First cut left =/api/login= on the desktop admin port, where it 500'd
  against the nil password — now the desktop admin port has no login surface
  at all (covered by =routes-test/desktop-admin-port-is-always-admin=).
- =ring-mock= is Clojars-only and the build container resolves from central,
  so =routes_test.clj= hand-rolls request maps instead.
- =transcode.clj= derives =ffprobe= from =FFMPEG_PATH= (sibling file,
  =ffmpeg(.exe)? → ffprobe$1=) and skips =nice= on Windows.
- =watch.cljs= keeps the =admin?= link hidden unless =welcome= says
  =:is-host=; =admin.cljs= hides the logout button inside the desktop shell
  (no logout on the admin port) and shows the sharing card instead.
- Room links inside the desktop shell use the tunnel URL (=public-base=
  atom, refreshed via a =goob:tunnel= DOM event) so "copy link" hands out
  something friends can actually open.
- electron-builder 25 rejects a per-target =zip= artifactName sub-config;
  the CI zip fallback globs =*-win-x64.zip= instead.
- Verified locally: 13 tests / 53 assertions; two-port invariants live
  (public 404s =/api/admin/*=, admin port always-admin); live quick tunnel
  404s the admin API; packaged AppImage (280 MB) boots the bundled
  JRE+jar+ffmpeg+cloudflared end-to-end incl. tunnel URL in the sharing
  card; container mode login regression green. Windows NSIS path is
  wine-dependent and gets its first real run in CI.
- *v0.1.1 hotfix* (first real Windows first-run found it): the migration
  runner listed =resources/migrations= from the *filesystem*, which is
  empty from the packaged app's CWD — a fresh install silently migrated
  zero tables and died at boot with /no such table: videos/. Migrations
  are now enumerated as a constant and loaded via =io/resource= (the
  classpath works from repo, container, and uberjar alike) and a missing
  migration throws instead of going silent. Half-migrated v0.1.0 DBs
  self-heal on next launch. Regression tests: classpath resolution +
  fresh-DB schema creation (15 tests / 56 assertions).
- *v0.1.2 hotfix* (second Windows report: page, chat, and MPD all fine but
  the video spun forever): BluRay-rip sources carry multi-channel audio
  (AC-3/E-AC-3/DTS 5.1), and ffmpeg's AAC encoder writes a PCE for layouts
  that don't match the standard AAC channel configs — Chrome's decoder
  rejects PCE streams, so MSE append failed (CHUNK_DEMUXER_ERROR_APPEND_FAILED)
  and dash.js never got past the spinner. Audio now transcodes
  =-c:a aac -b:a 128k -ac 2=: stereo is universal, and a watch party over a
  quick tunnel doesn't need 5.1. Reproduced locally with a synthetic
  x265-10bit + E-AC-3 5.1 mkv (spinner, matching the report) and verified
  the fix yields AAC-LC stereo with standard channel configuration.
  Videos transcoded before the fix keep their bad audio track — delete and
  re-upload to re-transcode.
- *CI moved to GitHub Actions*: srht.site serves the installers at ~2 MB/s
  (measured), so releases moved to GitHub Releases
  (=.github/workflows/release.yml=: jar built once, AppImage on ubuntu +
  NSIS on windows in parallel, attached via =gh release create --repo=).
  =.builds/= retired; =README= links use =/releases/latest/download/= so
  they never rot. Gotchas learned: =secrets= is NOT available in =if:=
  expressions (gate on a step output instead), and =actionlint= catches
  schema errors that plain YAML parsing does not. The plans-site publish
  needs an =SRHT_TOKEN= repo secret (sourcehut OAuth, pages scope) and is
  skipped without it.
- *v0.1.3*: the server now logs its version at boot (first line of
  =server.log=). The Windows logs proved the migration fix landed but could
  not distinguish v0.1.1 from v0.1.2 — no more guessing whether a user
  actually updated. =GOOB_VERSION= env (Electron passes =app.getVersion()=)
  wins, else the =goob-toob.version= resource stamped into the jar by
  =build.clj= (=VERSION= env or =git describe=), else =dev=. Gotcha:
  =b/write-file= pr-prints strings (writes them quoted) — use =spit=.
