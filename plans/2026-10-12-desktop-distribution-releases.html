Goal

Turn goob-toob into a double-click desktop app for Windows (primary audience) and Linux. An Electron shell owns the Clojure server, a vendored cloudflared gives the admin a public URL to toss at friends with zero setup, the admin password disappears for desktop mode (loopback-only admin port instead), the storage folder is picked in-app, and builds.sr.ht produces the installers, published to srht.site and linked from the repo front page.

Findings

  • Boot today: clojure -M:dev -m goob-toob.core (container/Containerfile:26); config/load! requires STORAGE_DIR and ADMIN_PASSWORD (src/clj/goob_toob/config.clj:29-34); one Jetty on one port (src/clj/goob_toob/core.clj:14-19).
  • Router: all admin API lives under one /api/admin subtree behind require-admin (src/clj/goob_toob/routes.clj:196-204); WS host status is the session cookie (src/clj/goob_toob/ws.clj:44). The admin SPA already asks /api/admin/me to decide login-vs-console (src/cljs/goob_toob/admin.cljs).
  • ffmpeg is called as bare ffmpeg with a Linux-only nice -n 10 prefix (src/clj/goob_toob/services/transcode.clj:54) — no configurable path, breaks on Windows.
  • No uberjar task exists (deps.edn has no :build alias).
  • CI today (.build.yml): alpine → plans site → hut pages publish to nathanb.srht.site/goob-toob-plans. srht.site limit: 1 GiB per site (tarball after decompression), no per-file cap — installers fit if we keep only the latest per platform.
  • git.sr.ht has no release files; builds.sr.ht artifacts expire in 90 days → releases go to nathanb.srht.site/goob-toob-releases/ (decided).
  • builds.sr.ht runs Linux VMs only. electron-builder cross-packages Windows from Linux natively; wine is needed only for the NSIS installer (electron.build docs) — so the portable zip is wine-free (decided: NSIS + zip fallback).
  • cloudflared quick tunnel: cloudflared tunnel --url http://127.0.0.1:PORT dials out (no open ports), prints an ephemeral https://<random>.trycloudflare.com, no account needed; Apache-2.0 so the binary is redistributable. Binaries: cloudflared-linux-amd64, cloudflared-windows-amd64.exe from GitHub releases.
  • Security fact that drives the auth design: cloudflared runs on the same box, so loopback checks can't protect the admin API — anything on the tunneled port is public. Decided design: two ports. Public port (lobby, watch, dash, WS, /api/me) gets the tunnel; a second Jetty bound to 127.0.0.1 serves the admin API + admin SPA + an always-host WS and is never tunneled. Container mode keeps ADMIN_PASSWORD login unchanged.
  • Licensing of bundled parts: Temurin JRE (GPLv2+CE, bundling is standard), ffmpeg static builds (GPL — separate process, ship license + source pointer), cloudflared (Apache-2.0), Electron (MIT). App itself is AGPL.

Plan

1 · Server: desktop mode with two ports

  1. src/clj/goob_toob/config.clj: ADMIN_PASSWORD becomes optional. Mode = :desktop when unset, :container when set (current behavior). New keys: :admin-port (GOOB_ADMIN_PORT, default 8081), :ffmpeg-path (FFMPEG_PATH, default "ffmpeg"). STORAGE_DIR stays required in both modes.
  2. src/clj/goob_toob/routes.clj: app takes {:keys [admin?]}. When admin? is false: omit the /api/admin subtree, /login, /logout and the /admin SPA route. New wrap-desktop-admin middleware (assoc :goob/admin true) wraps the admin-port handler; whoami returns {:admin true} when that attribute is present.
  3. src/clj/goob_toob/ws.clj: admin? = (or (:goob/admin req) session :admin) — admin-port sockets are always host, public-port sockets unchanged.
  4. src/clj/goob_toob/core.clj: desktop mode starts two Jetty servers — public on :port (all interfaces) and admin on :admin-port with :host "127.0.0.1" (Jetty option). Container mode: single server, as today.
  5. src/clj/goob_toob/services/transcode.clj: ffmpeg binary from :ffmpeg-path; drop the nice prefix on Windows ((.contains (System/getProperty "os.name") "Windows")).
  6. src/cljs/goob_toob/watch.cljs: hide the "admin?" header link unless the welcome said :is-host (it would 404 on the public port).

2 · Build chain: uberjar + vendored binaries

  1. deps.edn: add :build alias (io.github.clojure/tools.build) + build.clj → target/goob-toob.jar uberjar.
  2. scripts/fetch-vendor.sh: pinned downloads into vendor/<platform>/ — cloudflared-linux-amd64 / cloudflared-windows-amd64.exe (GitHub release, pinned tag) and static ffmpeg (johnvansickle linux / BtbN win64-gpl), each sha256-checked. Makefile target vendor.
  3. Makefile: uberjar, vendor, desktop (electron-builder --dir + run, local dev loop).

3 · Electron shell (desktop/)

  1. desktop/package.json (electron, electron-builder, electron-store), main.js, preload.js, icon. Boot sequence:
    • read stored storageDir; if none → dialog.showOpenDialog first run.
    • spawn bundled JRE: java -jar <res>/goob-toob.jar with env STORAGE_DIR, PORT (free ephemeral), GOOB_ADMIN_PORT (free), FFMPEG_PATH (bundled); wait for GET /api/admin/me 200.
    • spawn cloudflared tunnel --url http://127.0.0.1:<public> --no-autoupdate; parse the trycloudflare URL from stderr.
    • open BrowserWindow at http://127.0.0.1:<admin-port>/admin (no login — admin port is always-admin).
    • preload exposes window.goob = {tunnelUrl, storageDir, pickStorageDir(), openWatch(token)} via contextBridge + IPC.
    • pickStorageDir → dialog → save config → restart server child → reload. Existing videos keep working (DB stores absolute paths); the new folder applies to new uploads. (Move-library is a follow-up.)
    • quit / window-close kills both children; single-instance lock.
  2. src/cljs/goob_toob/admin.cljs: a "sharing" card rendered only when window.goob exists: tunnel URL + copy button, storage folder + change button. Container mode never sees it.
  3. electron-builder config: appId org.goobtoob.app; linux AppImage; win nsis + zip; extraResources: jar, jre/ (Temurin per platform), ffmpeg, cloudflared, =THIRD-PARTY.org~ (licenses). No code signing.

4 · CI: .builds/release.yml (manual: hut builds submit after tagging)

  1. fedora image (java-25, nodejs, wine, zip, unzip — matches the container). Tasks: uberjar + shadow-cljs release client → vendor downloads (both platforms) + Temurin JRE zips (linux + win, Adoptium API, pinned) → electron-builder --linux AppImage --win nsis zip → artifact: every installer → publish task gated on git describe --exact-match 'v*' : publishes only the AppImage + NSIS setup.exe (the zip duplicates the installer's payload; it stays a CI artifact and is published only if the wine/NSIS step failed) + tiny index.html (links + sha256sums) + tar → hut pages publish -d nathanb.srht.site -s /goob-toob-releases. Stable filenames (goob-toob-setup.exe, goob-toob.AppImage, goob-toob-win.zip) so README links never rot.
  2. Version: desktop/package.json version == git tag; bump at release.

5 · Front page

  1. README.md: a Download section at the very top — Windows → goob-toob-setup.exe, Linux → goob-toob.AppImage, each a direct nathanb.srht.site link (the portable zip is linked only in releases where it was the published Windows build), plus the SmartScreen note ("More info → Run anyway") and a pointer to the podman path for server folks. README.org: desktop quickstart section.

Risks and open questions

  • srht.site budget: 1 GiB per site shared with the plans site. Publishing only the AppImage + NSIS installer (the zip would duplicate the installer's payload) puts the release set at ≈ 450–500 MB — comfortable headroom. The heavy parts (Electron runtime, JRE, ffmpeg, cloudflared) are all platform-specific binaries; the shared JS is ~2 MB, so a combined cross-platform artifact would only make every user download both platforms' runtimes. If the budget ever tightens, jlink-trim the JRE or move releases to Codeberg (links are one file).
  • wine/NSIS flakiness in CI: the portable zip is always built, so a wine hiccup costs the installer, never the release.
  • Unsigned Windows exe → SmartScreen "unknown publisher" warning; documented in README. Code signing certs are out of scope.
  • Quick tunnels are personal-use per Cloudflare ToS: ephemeral URL per launch, no uptime promise. Right-sized for a watch party; say so in README.
  • Two-port invariant: the public port must never gain admin routes — regression-tested (new CLJ test asserts 404 on /api/admin/* when admin? is false).
  • Full Temurin JRE bundled (~45 MB compressed) rather than jlink-trimmed: robust first, jlink later as a size win.
  • ffmpeg is GPL and cloudflared Apache: bundle =THIRD-PARTY.org~ with licenses + source pointers; AGPL app source = the repo link.
  • Storage-dir change applies to new uploads only (absolute paths in DB); "move library" is a follow-up plan.
  • Auto-update: out of scope; README says "download the latest".
  • Container mode must not regress: ADMIN_PASSWORD set → today's single-port behavior, byte-for-byte.

Verification

  1. make test — new route tests: app {:admin? false} → /api/admin/videos 404, /login 404; app {:admin? true} + wrap-desktop-admin → /me {:admin true} without a session. Container-mode tests unchanged.
  2. Local desktop loop: make uberjar vendor → cd desktop && npm start: first-run folder picker → window shows admin console no login → sharing card shows the tunnel URL → curl <tunnel>/api/admin/me must be 404 (proof the admin API is not exposed) → curl <tunnel>/api/me → {:admin false}.
  3. Upload via drop zone → transcode → make room → open the watch link (host, admin port) → native play → friend tab via the tunnel URL parks on the live frame → play → in sync; co-host toggle still live.
  4. Windows: hut builds submit .builds/release.yml on a v0.1.0 tag → artifacts present → installer runs in a Windows VM: first run, upload, tunnel URL, watch from a phone over the tunnel.
  5. Releases page nathanb.srht.site/goob-toob-releases/ lists installers + sha256; README.md links download the right binaries; make run (container mode) still logs in with ADMIN_PASSWORD as before.

Implementation notes

Shipped same day. Deviations and found issues:

  • app takes {:keys [admin? login?]}: login? is container-mode only. First cut left /api/login on the desktop admin port, where it 500'd against the nil password — now the desktop admin port has no login surface at all (covered by routes-test/desktop-admin-port-is-always-admin).
  • ring-mock is Clojars-only and the build container resolves from central, so routes_test.clj hand-rolls request maps instead.
  • transcode.clj derives ffprobe from FFMPEG_PATH (sibling file, ffmpeg(.exe)? → ffprobe$1) and skips nice on Windows.
  • watch.cljs keeps the admin? link hidden unless welcome says :is-host; admin.cljs hides the logout button inside the desktop shell (no logout on the admin port) and shows the sharing card instead.
  • Room links inside the desktop shell use the tunnel URL (public-base atom, refreshed via a goob:tunnel DOM event) so "copy link" hands out something friends can actually open.
  • electron-builder 25 rejects a per-target zip artifactName sub-config; the CI zip fallback globs *-win-x64.zip instead.
  • Verified locally: 13 tests / 53 assertions; two-port invariants live (public 404s /api/admin/*, admin port always-admin); live quick tunnel 404s the admin API; packaged AppImage (280 MB) boots the bundled JRE+jar+ffmpeg+cloudflared end-to-end incl. tunnel URL in the sharing card; container mode login regression green. Windows NSIS path is wine-dependent and gets its first real run in CI.
  • v0.1.1 hotfix (first real Windows first-run found it): the migration runner listed resources/migrations from the filesystem, which is empty from the packaged app's CWD — a fresh install silently migrated zero tables and died at boot with no such table: videos. Migrations are now enumerated as a constant and loaded via io/resource (the classpath works from repo, container, and uberjar alike) and a missing migration throws instead of going silent. Half-migrated v0.1.0 DBs self-heal on next launch. Regression tests: classpath resolution + fresh-DB schema creation (15 tests / 56 assertions).
