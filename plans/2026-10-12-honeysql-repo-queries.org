* Goal
Swap every hand-written SQL string in the persistence layer for
[[https://github.com/seancorfield/honeysql][HoneySQL]] data structures (=com.github.seancorfield/honeysql=
=2.7.1479=, current on Clojars), keeping =next.jdbc= as the executor. Pure
refactor: identical behavior, identical function signatures, identical result
shapes. =test/clj/goob_toob/repos_test.clj= is the gate — it must pass
*unchanged*.

  (=routes.clj=, =services/*= go through the repos).
- ~src/clj/goob_toob/repos/video.clj:13~ — 8 statements:
  - =insert!= (INSERT with inline ='uploaded'= literal), =get-by-id=,

  (~src/clj/goob_toob/repos/room.clj:35-37~), DELETE.
- ~src/clj/goob_toob/db.clj:17-29~ — migration runner: bootstrap
  =CREATE TABLE IF NOT EXISTS schema_migrations=, =SELECT name FROM

  The runner slurps =resources/migrations/*.sql= (~src/clj/goob_toob/db.clj:23~).
- Result rows are built with =rs/as-unqualified-kebab-maps= /
  =as-unqualified-lower-maps= — those stay untouched, so callers see the same

- =deps.edn= already has =next.jdbc 1.3.1118=; HoneySQL is not yet a dep.
- =sql/format= returns =[sql & params]= — exactly the vector shape
  =jdbc/execute!=/=execute-one!= already take, so call sites become

* Plan
1. *deps.edn*: add =com.github.seancorfield/honeysql {:mvn/version
   "2.7.1479"}= to =:deps=.
2. *repos/video.clj*: require =[honey.sql :as sql]=. Rewrite all 8
   statements as HoneySQL maps, e.g.:
   #+begin_src clojure
   ;; insert!
   (jdbc/execute! (db/db)
     (sql/format {:insert-into :videos
                  :values [{:id id :title title :original-path original-path
                            :dash-dir (str "dash/" id) :status "uploaded"}]}))

   ;; set-status! — COALESCE as a HoneySQL fn vector, datetime via [:raw ...]
   (jdbc/execute! (db/db)
     (sql/format {:update :videos
                  :set {:status status
                        :progress [:coalesce progress :progress]
                        :error error
                        :duration [:coalesce duration :duration]
                        :updated-at [:raw "datetime('now')"]}
                  :where [:= :id id]}))

   ;; requeue-stuck
   (sql/format {:select [:id] :from [:videos]
                :where [:in :status ["uploaded" "transcoding"]]})
   #+end_src
   A plain value in an expression position becomes a =?=? parameter
   automatically, so =COALESCE(?, col)= is =[:coalesce progress :progress]=
   — no raw SQL, param order guaranteed. =datetime('now')= carries no params,
   so =[:raw ...]= is safe there.
3. *repos/room.clj*: same treatment; the JOIN becomes
   #+begin_src clojure
   (sql/format {:select [[:r/id] [:r/token] [:r/video_id] [:v/title] [:v/status]]
                :from [[:rooms :r]]
                :join [:videos :v [:= :v.id :r.video_id]]
                :order-by [[:r/created-at :desc]]})
   #+end_src
   =as-unqualified-kebab-maps= keeps the result keys
   (=:id :token :video-id :title :status=) exactly as today.
4. *db.clj*: convert the two bookkeeping DML statements (=SELECT name FROM
   schema_migrations=, =INSERT INTO schema_migrations ...=) to HoneySQL.
   *Leave as raw SQL*: the bootstrap =CREATE TABLE IF NOT EXISTS= and the
   =resources/migrations/*.sql= files — DDL migrations as checked-in .sql
   files is the normal pattern and the runner already handles them.
5. No signature or result-shape changes anywhere; =storage.clj= untouched
   (filesystem, no SQL).

* Risks and open questions
- *Assumption*: migration =.sql= files and the bootstrap DDL stay raw.
  HoneySQL can emit =CREATE TABLE= but it buys nothing for versioned
  migrations. Say so if you want those converted too.
- Parameter-order bugs are the classic hazard — avoided by using HoneySQL
  placeholders/fn vectors instead of raw fragments containing =?=.
- HoneySQL kebab→snake conversion (=video-id= → =video_id=) matches the
  schema; the =IN= list renders as separate params, not interpolation.
- Container rebuild needed for the new dep (=make image= / =make test= pull
  it at build time).

* Implementation notes
Shipped 2026-10-12. Three deviations from the plan found by actually running
HoneySQL 2.7.1479 (the plan's first-draft snippets were wrong):
- =honey.sql.raw= does not exist in 2.x — raw SQL is the =[:raw "..."]=
  vector form inside expressions.
- =:set= as a vector of pairs renders garbage (=SET 0 = STATUS(?)=) in
  2.7.1479; the map form =:set {:col val ...}= is the one that works.
- =IN= is prefix form with a collection: =[:in :status ["a" "b"]]=;
  =[:status [:in "a" "b"]]= parses =:status= as a function call.
All caught by =make test= and a live container smoke (upload → transcode →
ready, room create/JOIN/WS/delete, video delete). 8 tests / 31 assertions
green with =repos_test.clj= unchanged.
