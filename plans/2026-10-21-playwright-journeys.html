Goal

A small suite of end-to-end tests drives goob-toob the way a party does: real browsers (Chromium, Firefox and WebKit, all from Playwright's own builds), real dash.js, real H.264 segments from the real transcode, real websockets, two or three browser contexts in one room. Each journey samples a metrics probe on the page and the server's own view of the room, and asserts summaries of those series (drift after settle, seeks, stalls, rate bounds, time to sync) against one thresholds table. The specs are ClojureScript compiled by shadow-cljs. The suite runs locally in a container (make e2e) and as its own CI job, and writes a metrics table into the job summary so a run says more than pass or fail. Once it is green in CI, the JVM suite shrinks to what a browser cannot reach: pure math, adversarial protocol input, migrations, and failure modes. This plan comes before autoplay and playlists; both then add journeys here instead of manual verification lists.

The thesis, and where it holds

Nathan's framing: most of the truly valuable tests of this repository could be a small set of Playwright journeys asserting on metrics, with more granularity than pass/fail and none of the drift of unit tests that pin implementation. Taking that seriously:

  • It holds for everything user-facing. The product is "watch in sync". Its value is measurable: drift, stalls, seeks, catch-up rate, time to join. Those are properties of the whole system (server clock, websocket, dash.js buffering, the element's playbackRate, the browser's autoplay policy) and no JVM test touches more than one of them. The lockdown's HTTP and websocket wiring tests prove the server speaks the protocol; a journey proves the party works. When both exist, the wiring tests are the ones that break on harmless refactors.
  • It does not hold for three kinds of test, which stay on the JVM.
    1. Pure logic with many branches (policy, room-rate, quality-cap, ladder-for, parse-range). A journey samples them under one real condition with wide tolerances; a table test covers every branch in milliseconds. This is the one place unit tests are the right tool, and cljc was built for it.
    2. Adversarial and security input: a viewer sending cmd without control, a string pos, a non-object frame, path traversal, the login limiter, the two-port split. A browser journey can reach some of these through page.evaluate and a raw WebSocket, but they are protocol tests wearing a costume. Keep them where they are cheap and exact.
    3. Time and failure: the 180 s give-up window, a crashed transcode's error text, a missing original, migrations on an old database. Not affordable or not reachable from a browser.
  • Metrics are the right assertion language for a sync product, with one discipline: thresholds live in one data file, assertions are on summaries over a window (p95, max after settle, counts), never on a single sample, and every journey writes its series to disk so a regression shows as a number moving before it shows as a failure.

Verdict: build the journeys, then retire the JVM tests that only pin wiring (list in Decisions). The suite that remains is about 100 JVM tests of logic and hostility plus about a dozen journeys of value, each run in three engines.

Findings

  • Nothing browser-driven exists. test/ is Clojure only; package.json has dash.js alone; no browser on the host. Every plan's browser verification so far was manual in two tabs.

  • Codecs: measured, not assumed. The worry was that open-source browser builds lack H.264 and AAC, which is the whole ladder (src/clj/goob_toob/services/transcode.clj:87-93). A probe in Playwright's official image (mcr.microsoft.com/playwright:v1.64.1-noble, with the ffmpeg apt package added, which the e2e image needs anyway for the clip) launched all four engines against a libx264 High + AAC-LC file and a VP9 + Opus file, checked MediaSource.isTypeSupported for the strings dash.js will ask about, and played each file for 1.5 s:

    engine avc1.64001f / avc1.4d401f / mp4a.40.2 (MSE) libx264+AAC playback VP9+Opus
    Chromium 156, Playwright build true / true / true currentTime 1.46, 49 frames plays
    Google Chrome 156, channel true / true / true currentTime 1.46, 49 frames plays
    Firefox 157, Playwright build true / true / true currentTime 1.47, 45 frames plays
    WebKit, Playwright build true / true / true currentTime 1.50, 46 frames plays

    Every engine decodes the ladder. Firefox and WebKit use the system libavcodec / GStreamer that the Playwright image carries; Chromium's Playwright build has the codecs itself. The branded-Chrome channel adds nothing. Playwright cannot drive a stock Firefox or Safari (it needs its own patched builds), so these three builds are the whole menu, and all three are in.

  • Autoplay policy knobs differ per engine. Chromium: --autoplay-policy=user-gesture-required (strict) or no-user-gesture-required as launch args. Firefox: firefoxUserPrefs {"media.autoplay.default" 1} (block audible, allow muted; the shipped default), 0 allow all, 5 block all. WebKit: no launch-time knob in Playwright; its behaviour is recorded, not forced. The autoplay plan's branches are therefore deterministic in Chromium and Firefox and observed in WebKit.
  • Network shaping is Chromium-only: a CDP session gives Network.emulateNetworkConditions. The throttled journey runs in the Chromium project only.
  • The page already measures everything. st on the watch page (src/cljs/goob_toob/watch.cljs:387-389) holds offset, mode, qcap, started, buffering; expected-now (watch.cljs:38-42) and buffer-ahead (watch.cljs:55-60) compute the rest. The clientlog path (routes.clj:140-145) already ships :seek-back, :stalled, :quality-cap, :started events to the server log. Nothing is exposed to a test.
  • The server already measures every client. rooms* (src/clj/goob_toob/services/sync.clj:12) holds per-client :drift, :at, :buffering, :behind-since and the room's :rate, :playing?; client-drifts (sync.clj:93-96) derives ages. There is no read endpoint.
  • Upload and transcode are reachable over HTTP (routes.clj:102-114) with the admin session; make clip shows the lavfi recipe. A 60 s 1280x720 clip transcodes to three rungs in well under a minute in the container.
  • shadow-cljs can emit what Playwright loads. The :esm target with :runtime :node writes one ES module per :modules entry and supports :exports {default ns/var}, so the Playwright config, the global setup and every spec file can be ClojureScript. @playwright/test registers tests with top-level test() calls, which namespace top-level forms provide. core.async is already a dependency; cljs.core.async.interop/<p! awaits promises inside go, and a go block converts to the Promise Playwright expects with one small wrapper.
  • The join gesture. Chromium toggles playback when a <video controls> surface is clicked, and a Playwright click is a real user activation; Firefox and WebKit may not toggle on surface click. Space on the focused element is the portable gesture.
  • CI today (.github/workflows/ci.yml): test (JVM + build smoke), tag (release on main), plans (Pages). The test job already installs Java, Clojure, Node and ffmpeg.

Decisions

Each with the evidence; Nathan flips what he disagrees with.

  • Specs, config and setup are ClojureScript, a second shadow-cljs build :e2e (:target :esm :runtime :node) under e2e/src, emitted into e2e/out/. The repo stays 100 % Clojure/CLJS. Cost: one build step before playwright test, which make e2e runs.
  • Three engines, one suite. Playwright projects chromium, firefox, webkit; every journey runs in all three except the throttled one (Chromium only, CDP). Measured above: all decode the ladder. The manual Firefox and Safari matrix in the autoplay plan shrinks to a real Safari spot check.
  • The e2e image is Playwright's official image plus Java, Clojure and ffmpeg, not Fedora plus browsers. The browsers and their system libraries are the hard part and Microsoft maintains that; Java and Clojure are two apt and curl lines. It is a separate image from the Fedora test image; make test is unchanged.
  • One metrics probe in product code. watch.cljs exposes a read-only window.goobProbe() returning the page's view (below). It is also a support tool: paste it in devtools on a user's machine. Cost: a few lines and a counters object.
  • One read endpoint on the admin API. GET /api/admin/rooms/:id/live returns the live room: :pos :t0 :playing :rate :now and every client's :nick :drift :age-ms :buffering :behind-ms. Admin-only, loopback on desktop. The authority's own numbers are what the room acts on, so journeys assert on both the page and the server.
  • Thresholds are data. goob-toob.e2e.thresholds is one map; specs read names from it; no numeric literal in a spec. Per-journey series go to e2e/metrics/<engine>-<spec>-<title>.json; CI uploads them and prints a table to the job summary.
  • Each journey makes its own room; the clip is shared. Global setup logs in, generates a 60 s clip with ffmpeg, uploads it, waits for ready. Rooms are cheap and isolate state.
  • Local loop is the container, container/Containerfile.e2e, with make e2e-image and make e2e. CI is the confirming run.
  • Retire wiring tests after five green CI runs, in a follow-up PR that this plan names (below). Not in the same PR: a journey that is flaky on the runner must not take a working test with it.
  • Soft metrics first for the throttled journey. Bandwidth shaping on a shared runner is the least deterministic thing here; its numbers are recorded and printed for a few runs before any threshold is asserted.

Plan

1 · Probe and live endpoint (product code, small)

src/cljs/goob_toob/watch.cljs

  • st gains "counters" (js-obj "seeks" 0 "stalls" 0 "seekbacks" 0 "rejected" 0 "capsteps" 0); increment at: park! and every ourseek write (seeks), onwaiting (stalls), the :seek-back branch (seekbacks), :play-rejected (rejected), a cap change in quality-event! (capsteps).

  • In page, after st exists: 

    (set! (.-goobProbe js/window)
      (fn []
        (let [room (.-room st) v (ui/$ "video")]
          (clj->js {:t (ui/perf-now)
                    :currentTime (some-> v .-currentTime)
                    :expected (when room (expected-now st room))
                    :drift (when (and room v) (sc/drift (.-currentTime v) (expected-now st room)))
                    :rate (some-> v .-playbackRate) :roomRate (:rate room)
                    :playing (:playing room) :paused (some-> v .-paused)
                    :muted (some-> v .-muted) :started (.-started st)
                    :mode (name (.-mode st)) :buffering (.-buffering st)
                    :bufferAhead (when v (buffer-ahead v))
                    :qcap (:cap (.-qcap st)) :offset (.-offset st)
                    :counters (js->clj (.-counters st))}))))

    expected-now and buffer-ahead move above page if needed; nothing else changes.

src/clj/goob_toob/routes.clj and sync.clj

  • sync/live-view [room-id] returns {:pos :t0 :playing :rate :now :clients [{:nick :drift :age-ms :buffering :behind-ms}]} from rooms* via client-drifts (now needs :nick and :buffering in the derived map: add them). nil for an unknown room.
  • Route ["/rooms/:id/live" {:get room-live}] in the admin group: 200 with the map, 404 when nil.
  • JVM tests: live-view-reports-every-client (sync_service_test: two clients, one 4 s behind → drifts and :behind-ms as expected) and room-live-is-admin-only (routes_test: 401 without session, 200 with, 404 unknown room).

:source-paths gains "e2e/src". :js-provider :import keeps @playwright/test and node:fs as real imports resolved from e2e/node_modules. The implementer confirms the default export shape Playwright wants with npx playwright test -c out/config.js --list before writing a journey; if :exports {default ...} does not produce export default, the fallback is a one-line e2e/playwright.config.js that re-exports out/config.js, and that line is the only JavaScript in the repo.

config.cljs

(ns goob-toob.e2e.config
  (:require ["@playwright/test" :refer [defineConfig devices]]))

(def port (or (.. js/process -env -GOOB_E2E_PORT) "18080"))
(def ci? (some? (.. js/process -env -CI)))

(def config
  (defineConfig
    (clj->js
     {:testDir "./out"
      :testMatch #js ["**/*.js"]
      :testIgnore #js ["**/config.js" "**/setup.js" "**/shared/**"]
      :timeout 120000 :fullyParallel false :workers 1 :retries (if ci? 1 0)
      :reporter [["list"] ["html" {:open "never" :outputFolder "report"}]]
      :globalSetup "./out/setup.js"
      :use {:baseURL (str "http://127.0.0.1:" port)
            :trace "retain-on-failure" :video "retain-on-failure"}
      :projects [{:name "chromium" :use {:browserName "chromium"
                                         :launchOptions {:args ["--autoplay-policy=user-gesture-required"]}}}
                 {:name "firefox"  :use {:browserName "firefox"
                                         :launchOptions {:firefoxUserPrefs {"media.autoplay.default" 1}}}}
                 {:name "webkit"   :use {:browserName "webkit"}}]
      :webServer {:command "clojure -M:dev -m goob-toob.core"
                  :cwd ".." :url (str "http://127.0.0.1:" port "/api/me")
                  :env {:STORAGE_DIR (.. js/process -env -GOOB_E2E_STORAGE)
                        :ADMIN_PASSWORD "pw" :PORT port}
                  :timeout 120000 :reuseExistingServer (not ci?)}})))

GOOB_E2E_STORAGE is a fresh temp dir made by make e2e / the CI step. The autoplay plan adds a chromium-lenient project with no-user-gesture-required and a firefox-lenient one with media.autoplay.default 0. workers 1 because journeys share one server and the sync metrics are timing-sensitive. The shadow :modules names decide the file names under out/; the testIgnore keeps shadow's shared chunk and the config out of the test list (adjust to what shadow actually emits).

journey.cljs

(ns goob-toob.e2e.journey
  (:require-macros [goob-toob.e2e.journey])
  (:require [cljs.core.async :as a]))

(defn chan->promise [ch]
  (js/Promise. (fn [res rej]
                 (a/take! ch (fn [v] (if (instance? js/Error v) (rej v) (res v)))))))

with the macro (in journey.clj): 

(defmacro defjourney
  "(defjourney \"title\" [{:keys [page browser] :as fx} info] body...)
  Registers a Playwright test whose body runs in a go block; <p! awaits
  promises. A thrown error rejects the test."
  [title [fx info] & body]
  `(~'test ~title
    (fn [~fx ~info]
      (goob-toob.e2e.journey/chan->promise
       (cljs.core.async/go
         (try ~@body
              (catch :default e# e#)))))))

Specs (:require ["@playwright/test" :refer [test expect]] [cljs.core.async.interop :refer-macros [<p!]]).

setup.cljs

run returns a Promise: request.newContext() → POST /api/login → keep the ring-session cookie; run ffmpeg -f lavfi -i testsrc2=size=1280x720:rate=30:duration=60 -f lavfi -i sine=frequency=440:duration=60 -c:v libx264 -preset veryfast -c:a aac -shortest clip.mp4 via node:child_process in the storage dir; POST /api/admin/upload multipart; poll /api/admin/videos until the row is ready (120 s budget, fail with the row's error text otherwise); write {:cookie :video-id :duration} to .fixture.json.

party.cljs

  • host : new context with the session cookie on 127.0.0.1, localStorage goob-nick = "host" via addInitScript, page at /watch/<token>; waits for the title to leave "joining the goo…".
  • viewer : same without the cookie, nick given.
  • join! : focus the video and press Space; if goobProbe().started is still false after 1 s, click the video surface. Waits for started.
  • play! / pause! / seek! : the host row's buttons and range input via getByRole.
  • inject! : video.currentTime + delta= in the page.

metrics.cljs

  • sample : polls goobProbe() every 250 ms for a window; returns the series as maps.
  • summarize : {:drift-abs-max :drift-abs-p95 :drift-final :rate-min :rate-max :stalls :seeks :seekbacks :muted :started-at} with the drift stats computed only after a settle period.
  • record! : writes metrics/<project>-<file>-<title>.json with series and summary, attaches the summary to the Playwright report, appends a Markdown row to metrics/summary.md.
  • live : the server's drifts per nick from the live endpoint.

thresholds.cljs (initial values; tune from the first recorded runs)

(def T
  {:start-within     5000    ; ms from gesture to started
   :park-drift       1.0     ; s, parked frame vs room before joining
   :sync-within      8000    ; ms until |drift| < :settled after joining
   :settled          0.5     ; s
   :steady-p95       0.5     ; s over the sampled window after settle
   :pause-agreement  0.3     ; s between two paused elements
   :catch-rate       [1.04 1.06]
   :nudge-rate       [0.94 0.96]
   :room-slow-rate   0.97
   :room-slow-within 4000    ; ms from laggard status to rate 0.97 at the server
   :closing-min      0.02    ; s of drift recovered per s while catching up
   :resync-within    15000   ; ms after the network returns
   :chat-within      2000})

3 · Journeys

Each journey records its summary per engine; the assertions column is what fails it. "server" means the live endpoint. Every journey runs in all three projects unless marked.

host_and_viewer.cljs

journey steps asserts
host starts the party host joins (gesture), play; sample 6 s started within :start-within; currentTime advances ≥ 4 s in 6 s; server playing true; 0 stalls
viewer joins a playing room in sync host playing 5 s in; viewer opens page; wait for parked; join; sample 20 s parked drift ≤ :park-drift; drift ≤ :settled within :sync-within; :drift-abs-p95 ≤ :steady-p95 after settle; server drift for the viewer ≤ :settled at the end; seeks after join = 0; seekbacks = 0
pause, seek and resume agree both playing; host pause; host seek +30 s; host play; sample 10 s after pause both paused, currentTime within :pause-agreement; after seek both within :pause-agreement of the seek target; after play the viewer's p95 ≤ :steady-p95

sync_policy.cljs

journey steps asserts
a laggard catches up without seeking viewer synced; inject! -3; sample 30 s rate within :catch-rate within 2 s; seekbacks = 0 and seeks = 0 over the window; drift improves by ≥ :closing-min × window seconds; server shows rate 0.97 within :room-slow-within; host page's slow note names the viewer
an early viewer is pulled back once inject! +3; sample 10 s exactly one seekback; drift ≤ :settled within 3 s; rate back within 0.01 of the room rate afterwards
a slightly early viewer is nudged, not seeked inject! +1.0; sample 15 s seekbacks = 0; rate within :nudge-rate at some sample; drift ≤ :settled by the end
throttled viewer steps the quality down (chromium, soft) CDP throttle to 1500 kbit/s before join; join; sample 40 s recorded only: stalls, qcap, capsteps, drift p95, server rate. Asserted: the page is still playing at the end (currentTime advanced in the last 10 s)

control.cljs

journey steps asserts
a viewer cannot drive until the host allows it viewer page: host row hidden; raw js/WebSocket from page.evaluate sends cmd pause server playing stays true for 2 s; then admin PATCH allow-control true; viewer reloads: host row visible, badge "co-hosting"; viewer pause → server playing false within 2 s, host's element paused

lobby_admin_chat.cljs

journey steps asserts
upload to lobby admin page: upload a second clip via the file input; watch the library row row goes uploaded → transcoding → ready within 90 s with the bar moving; lobby shows no card until a room exists; make room → lobby card with the title; delete room → card gone
chat round trip host and viewer; host sends; viewer scrolled up receives viewer sees the bubble within :chat-within with the host's nick; the new-messages pill appears when scrolled up and clears on click

resilience.cljs

journey steps asserts
a dropped socket resyncs viewer synced; context.setOffline(true) 6 s; host seeks +20 s meanwhile; online peers list on the host drops then regains the viewer; viewer drift ≤ :settled within :resync-within; no more than one seek after reconnect
a late joiner parks on the live frame host 8 s in; viewer opens; sample 3 s before joining started false; paused true; parked drift ≤ :park-drift on every sample (re-park tracks the room)

About a dozen journeys; three engines; target under ten minutes in the container, with the engines run as separate CI matrix legs so each is under four.

Risks and open questions

  • Timing on shared runners. The sync journeys measure seconds of wall-clock behaviour. Mitigations: workers 1, one retry in CI, summaries over windows with a settle period, thresholds tuned from recorded runs before being tightened, and the throttled journey kept soft. A journey that flakes twice gets its threshold loosened or its assertion moved to recorded-only, never a sleep.
  • Three engines triple the timing surface. The matrix runs them in parallel legs so wall time stays near one engine's; a journey that is solid in Chromium and flaky in one other engine is allowed a per-engine threshold entry in T rather than a skip.
  • shadow :esm details. The default export shape, the shared-chunk file name, and :js-provider :import resolving from e2e/node_modules are the three things to confirm with --list before writing journeys. The one-line re-export fallback is named above.
  • Gestures in Firefox and WebKit. Space on the focused element is the portable gesture; the surface click is the Chromium fallback. If a journey cannot start a viewer in one engine, that is a finding about the product (the join affordance), not a reason to skip.
  • WebKit autoplay policy cannot be forced. The autoplay plan's branches are asserted in Chromium and Firefox and recorded in WebKit.
  • H.264 decode is software in all three engines. 720p at 30 fps was fine in the probe; if a runner drops frames, currentTime still advances and the metrics hold. The clip can drop to 480p if needed.
  • The probe is product code. It is read-only and unlisted; it costs a closure. Counters are the only new state.
  • reuseExistingServer locally lets an already running make dev server be reused on 18080; the storage dir must then match. The default make e2e path always starts its own.
  • The retirement list shrinks coverage of the admin HTTP API to the journeys. If the admin console is ever replaced, those journeys go with it and the API loses its tests. Accepted; the API's consumer is the console.
