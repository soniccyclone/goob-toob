* Goal
A small suite of end-to-end tests drives goob-toob the way a party does:
real browsers (Chromium, Firefox and WebKit, all from Playwright's own
builds), real dash.js, real H.264 segments from the real transcode, real
websockets, two or three browser contexts in one room. Each journey
samples a metrics probe on the page and the server's own view of the
room, and asserts summaries of those series (drift after settle, seeks,
stalls, rate bounds, time to sync) against one thresholds table. The
specs are ClojureScript compiled by shadow-cljs. The suite runs locally
in a container (=make e2e=) and as its own CI job, and writes a metrics
table into the job summary so a run says more than pass or fail. Once it
is green in CI, the JVM suite shrinks to what a browser cannot reach:
pure math, adversarial protocol input, migrations, and failure modes.
This plan comes before autoplay and playlists; both then add journeys
here instead of manual verification lists.

* The thesis, and where it holds
Nathan's framing: most of the truly valuable tests of this repository
could be a small set of Playwright journeys asserting on metrics, with
more granularity than pass/fail and none of the drift of unit tests that
pin implementation. Taking that seriously:

- *It holds for everything user-facing.* The product is "watch in sync".
  Its value is measurable: drift, stalls, seeks, catch-up rate, time to
  join. Those are properties of the whole system (server clock, websocket,
  dash.js buffering, the element's =playbackRate=, the browser's autoplay
  policy) and no JVM test touches more than one of them. The lockdown's
  HTTP and websocket wiring tests prove the server speaks the protocol;
  a journey proves the party works. When both exist, the wiring tests are
  the ones that break on harmless refactors.
- *It does not hold for three kinds of test, which stay on the JVM.*
  1. Pure logic with many branches (=policy=, =room-rate=, =quality-cap=,
     =ladder-for=, =parse-range=). A journey samples them under one real
     condition with wide tolerances; a table test covers every branch in
     milliseconds. This is the one place unit tests are the right tool,
     and =cljc= was built for it.
  2. Adversarial and security input: a viewer sending =cmd= without
     control, a string =pos=, a non-object frame, path traversal, the
     login limiter, the two-port split. A browser journey can reach some
     of these through =page.evaluate= and a raw =WebSocket=, but they are
     protocol tests wearing a costume. Keep them where they are cheap and
     exact.
  3. Time and failure: the 180 s give-up window, a crashed transcode's
     error text, a missing original, migrations on an old database. Not
     affordable or not reachable from a browser.
- *Metrics are the right assertion language for a sync product*, with one
  discipline: thresholds live in one data file, assertions are on
  summaries over a window (p95, max after settle, counts), never on a
  single sample, and every journey writes its series to disk so a
  regression shows as a number moving before it shows as a failure.

Verdict: build the journeys, then retire the JVM tests that only pin
wiring (list in Decisions). The suite that remains is about 100 JVM tests
of logic and hostility plus about a dozen journeys of value, each run in
three engines.

* Findings
- *Nothing browser-driven exists.* =test/= is Clojure only; =package.json=
  has dash.js alone; no browser on the host. Every plan's browser
  verification so far was manual in two tabs.
- *Codecs: measured, not assumed.* The worry was that open-source browser
  builds lack H.264 and AAC, which is the whole ladder
  (~src/clj/goob_toob/services/transcode.clj:87-93~). A probe in
  Playwright's official image (=mcr.microsoft.com/playwright:v1.64.1-noble=,
  with the =ffmpeg= apt package added, which the e2e image needs anyway
  for the clip) launched all four engines against a libx264 High + AAC-LC
  file and a VP9 + Opus file, checked =MediaSource.isTypeSupported= for
  the strings dash.js will ask about, and played each file for 1.5 s:
  | engine                          | avc1.64001f / avc1.4d401f / mp4a.40.2 (MSE) | libx264+AAC playback           | VP9+Opus |
  |---------------------------------+---------------------------------------------+--------------------------------+----------|
  | Chromium 156, Playwright build  | true / true / true                          | =currentTime= 1.46, 49 frames   | plays    |
  | Google Chrome 156, =channel=    | true / true / true                          | =currentTime= 1.46, 49 frames   | plays    |
  | Firefox 157, Playwright build   | true / true / true                          | =currentTime= 1.47, 45 frames   | plays    |
  | WebKit, Playwright build        | true / true / true                          | =currentTime= 1.50, 46 frames   | plays    |
  Every engine decodes the ladder. Firefox and WebKit use the system
  libavcodec / GStreamer that the Playwright image carries; Chromium's
  Playwright build has the codecs itself. The branded-Chrome channel adds
  nothing. Playwright cannot drive a stock Firefox or Safari (it needs its
  own patched builds), so these three builds are the whole menu, and all
  three are in.
- *Autoplay policy knobs differ per engine.* Chromium:
  =--autoplay-policy=user-gesture-required= (strict) or
  =no-user-gesture-required= as launch args. Firefox: =firefoxUserPrefs=
  ={"media.autoplay.default" 1}= (block audible, allow muted; the shipped
  default), =0= allow all, =5= block all. WebKit: no launch-time knob in
  Playwright; its behaviour is recorded, not forced. The autoplay plan's
  branches are therefore deterministic in Chromium and Firefox and
  observed in WebKit.
- *Network shaping* is Chromium-only: a CDP session gives
  =Network.emulateNetworkConditions=. The throttled journey runs in the
  Chromium project only.
- *The page already measures everything.* =st= on the watch page
  (~src/cljs/goob_toob/watch.cljs:387-389~) holds =offset=, =mode=,
  =qcap=, =started=, =buffering=; =expected-now= (~watch.cljs:38-42~) and
  =buffer-ahead= (~watch.cljs:55-60~) compute the rest. The =clientlog=
  path (~routes.clj:140-145~) already ships =:seek-back=, =:stalled=,
  =:quality-cap=, =:started= events to the server log. Nothing is
  exposed to a test.
- *The server already measures every client.* =rooms*=
  (~src/clj/goob_toob/services/sync.clj:12~) holds per-client =:drift=,
  =:at=, =:buffering=, =:behind-since= and the room's =:rate=,
  =:playing?=; =client-drifts= (~sync.clj:93-96~) derives ages. There is
  no read endpoint.
- *Upload and transcode are reachable over HTTP* (~routes.clj:102-114~)
  with the admin session; =make clip= shows the lavfi recipe. A 60 s
  1280x720 clip transcodes to three rungs in well under a minute in the
  container.
- *shadow-cljs can emit what Playwright loads.* The =:esm= target with
  =:runtime :node= writes one ES module per =:modules= entry and supports
  =:exports {default ns/var}=, so the Playwright config, the global setup
  and every spec file can be ClojureScript. =@playwright/test= registers
  tests with top-level =test()= calls, which namespace top-level forms
  provide. core.async is already a dependency; =cljs.core.async.interop/<p!=
  awaits promises inside =go=, and a =go= block converts to the Promise
  Playwright expects with one small wrapper.
- *The join gesture.* Chromium toggles playback when a =<video controls>=
  surface is clicked, and a Playwright click is a real user activation;
  Firefox and WebKit may not toggle on surface click. Space on the
  focused element is the portable gesture.
- *CI today* (~.github/workflows/ci.yml~): =test= (JVM + build smoke),
  =tag= (release on main), =plans= (Pages). The =test= job already installs
  Java, Clojure, Node and ffmpeg.

* Decisions
Each with the evidence; Nathan flips what he disagrees with.
- *Specs, config and setup are ClojureScript*, a second shadow-cljs build
  =:e2e= (=:target :esm :runtime :node=) under =e2e/src=, emitted into
  =e2e/out/=. The repo stays 100 % Clojure/CLJS. Cost: one build step
  before =playwright test=, which =make e2e= runs.
- *Three engines, one suite.* Playwright projects =chromium=, =firefox=,
  =webkit=; every journey runs in all three except the throttled one
  (Chromium only, CDP). Measured above: all decode the ladder. The
  manual Firefox and Safari matrix in the autoplay plan shrinks to a
  real Safari spot check.
- *The e2e image is Playwright's official image* plus Java, Clojure and
  ffmpeg, not Fedora plus browsers. The browsers and their system
  libraries are the hard part and Microsoft maintains that; Java and
  Clojure are two apt and curl lines. It is a separate image from the
  Fedora test image; =make test= is unchanged.
- *One metrics probe in product code.* =watch.cljs= exposes a read-only
  =window.goobProbe()= returning the page's view (below). It is also a
  support tool: paste it in devtools on a user's machine. Cost: a few
  lines and a counters object.
- *One read endpoint on the admin API.* =GET /api/admin/rooms/:id/live=
  returns the live room: =:pos :t0 :playing :rate :now= and every client's
  =:nick :drift :age-ms :buffering :behind-ms=. Admin-only, loopback on
  desktop. The authority's own numbers are what the room acts on, so
  journeys assert on both the page and the server.
- *Thresholds are data.* =goob-toob.e2e.thresholds= is one map; specs
  read names from it; no numeric literal in a spec. Per-journey series go
  to =e2e/metrics/<engine>-<spec>-<title>.json=; CI uploads them and
  prints a table to the job summary.
- *Each journey makes its own room; the clip is shared.* Global setup
  logs in, generates a 60 s clip with ffmpeg, uploads it, waits for
  =ready=. Rooms are cheap and isolate state.
- *Local loop is the container*, =container/Containerfile.e2e=, with
  =make e2e-image= and =make e2e=. CI is the confirming run.
- *Retire wiring tests after five green CI runs*, in a follow-up PR that
  this plan names (below). Not in the same PR: a journey that is flaky on
  the runner must not take a working test with it.
- *Soft metrics first for the throttled journey.* Bandwidth shaping on a
  shared runner is the least deterministic thing here; its numbers are
  recorded and printed for a few runs before any threshold is asserted.

*** =thresholds.cljs= (initial values; tune from the first recorded runs)
#+begin_src clojure
(def T
  {:start-within     5000    ; ms from gesture to started
   :park-drift       1.0     ; s, parked frame vs room before joining
   :sync-within      8000    ; ms until |drift| < :settled after joining
   :settled          0.5     ; s
   :steady-p95       0.5     ; s over the sampled window after settle
   :pause-agreement  0.3     ; s between two paused elements
   :catch-rate       [1.04 1.06]
   :nudge-rate       [0.94 0.96]
   :room-slow-rate   0.97
   :room-slow-within 4000    ; ms from laggard status to rate 0.97 at the server
   :closing-min      0.02    ; s of drift recovered per s while catching up
   :resync-within    15000   ; ms after the network returns
   :chat-within      2000})
#+end_src
Note (2026-10-27): every gate on a /landing/ (join, late join, reconnect
resync, resume after a seek) now uses =:landed=, read from the policy's
=:dead-band= (1.0 s); =:settled= 0.5 stays for drift after a policy action
(the nudge journey). A landing is a seek plus a buffering stall, and the
element comes back behind by that stall; the policy never corrects a lag
inside the dead band, so a 0.5 s gate could not be met from a 0.66 s
landing and "a late joiner lands on the live frame" failed its first
attempt in 3 of 18 main runs (and both attempts on two PRs).

Note (2026-10-27): Chromium's native controls toggle play on Space
/keyup/, at the target, and a keydown preventDefault does not reach it.
The host's keydown sends the room's play; when that state landed before
the release (a LAN round trip fits inside a human keypress) the release
paused the host's own element while the room played on, the "spinner at
0:00". The watch page now cancels the native toggle with a capture-phase
keyup preventDefault for a client that can control (a viewer who cannot
keeps it as the join gesture); "a held Space does not pause the host"
reproduces the race on purpose. In the same change "host starts the
party" opens its window only once the landing is over (=wait-landed!=:
started, not paused, not buffering): the landing stall used to fall
inside the window by timing luck and fail "0 stalls" (6 of 12 local runs,
1 in 18 on CI).

* Risks and open questions
- *Timing on shared runners.* The sync journeys measure seconds of
  wall-clock behaviour. Mitigations: =workers 1=, one retry in CI,
  summaries over windows with a settle period, thresholds tuned from
  recorded runs before being tightened, and the throttled journey kept
  soft. A journey that flakes twice gets its threshold loosened or its
  assertion moved to recorded-only, never a sleep.
- *Three engines triple the timing surface.* The matrix runs them in
  parallel legs so wall time stays near one engine's; a journey that is
  solid in Chromium and flaky in one other engine is allowed a per-engine
  threshold entry in =T= rather than a skip.
- *shadow =:esm= details.* The =default= export shape, the shared-chunk
  file name, and =:js-provider :import= resolving from =e2e/node_modules=
  are the three things to confirm with =--list= before writing journeys.
  The one-line re-export fallback is named above.
- *Gestures in Firefox and WebKit.* Space on the focused element is the
  portable gesture; the surface click is the Chromium fallback. If a
  journey cannot start a viewer in one engine, that is a finding about the
  product (the join affordance), not a reason to skip.
- *WebKit autoplay policy cannot be forced.* The autoplay plan's branches
  are asserted in Chromium and Firefox and recorded in WebKit.
- *H.264 decode is software in all three engines.* 720p at 30 fps was
  fine in the probe; if a runner drops frames, =currentTime= still
  advances and the metrics hold. The clip can drop to 480p if needed.
- *The probe is product code.* It is read-only and unlisted; it costs a
  closure. Counters are the only new state.
- *=reuseExistingServer= locally* lets an already running =make dev=
  server be reused on =18080=; the storage dir must then match. The
  default =make e2e= path always starts its own.
- *The retirement list shrinks coverage of the admin HTTP API to the
  journeys.* If the admin console is ever replaced, those journeys go
  with it and the API loses its tests. Accepted; the API's consumer is
  the console.

* Implementation notes
Implemented 2026-10-21 by three Opus subagents from this plan (step 1;
steps 2-5; step 6), reviewed and verified by the planning session; PR
for #40. Landed as specced, plus:

- *No JavaScript in the repo.* shadow's =:esm= =:exports {default ...}=
  gives Playwright the config it wants. Playwright reads fixture names by
  parsing the test function's source, which compiled CLJS cannot
  provide, so =defjourney= hands it a function whose =toString= names the
  fixtures, and emits the =test= call inside the spec's own namespace so
  the report attributes each test to its spec file rather than to the
  shared chunk. The =:e2e= build is =:optimizations :simple= with
  =:infer-externs false=.
- *One journey ships as an expected failure and one as a runtime skip*,
  each pinned to an issue. =a dropped socket resyncs= is =test.fail= in
  every engine (#41: a reconnect applies the room clock but never seeks
  the element, so a seek missed while offline leaves the viewer 19-38 s
  behind); it flips to "unexpected pass" when fixed, delete the mark
  then. =a laggard catches up without seeking= in WebKit hit
  =MEDIA_ERR_DECODE= on the injected backward seek 5/5 times locally and
  0/2 on the GitHub runner (#42), so a hard mark was wrong either way: the
  journey records its metrics with =:decode-error=, then skips at runtime
  with the issue only when the error happened, and asserts normally
  otherwise. dash.js clears =video.error= before a test can read it, so
  the journey captures the codes with a capture-phase =error= listener on
  =document= installed before the injection.
- *The parked frame sits at 0:00 for 3-4.4 s* in every engine: the park
  on stream-init runs before the first pong, so =expected= is computed
  with offset 0, and only the next pong lands it; between pongs the
  frozen frame drifts up to 5 s by design (re-parks follow the 5 s ping).
  Thresholds encode what was measured (=:park-live-within 7000=,
  =:park-track 5.5=). The autoplay plan's =ready?= gate (samples
  non-empty before starting) is the fix for the first part.
- *WebKit never starts on Space*; the click fallback always does, about
  1.1 s after the gesture. =join!= tries Space, then the surface click.
- *=setOffline= does not close an open WebSocket* in any engine, so the
  dropped-socket journey cuts it with =routeWebSocket= while =setOffline=
  still blocks segment fetches.
- *Thresholds changed from the plan*, each from recorded numbers:
  =:room-slow-within= 4000 → 6000 ms (a status every 2 s plus a tick
  every 2 s; recorded 2052-4213), =:closing-min= 0.02 → 0.05 s/s (healthy
  0.076-0.078; with the catch rate broken to 1.0 the room's 0.97 alone
  closes 0.027, which 0.02 would have passed), laggard injection -3.0 →
  -3.5 s (Firefox once reported 2.99 s and the room never slowed), clip
  60 → 90 s and the upload clip 180 s, =:parked-window= 3 → 12 s,
  =:nudge-window= 15 → 25 s after a CI flake at 0.72 s (a 0.95x nudge
  closes 0.05 s/s, so 1.0 s to the 0.15 s settle point is 17 s plus up to
  2 s to enter the nudge; 15 s only passed on a fast machine). Counts
  the plan stated as "exactly one" are =T= entries; step lengths and
  deltas are in a =W= map; specs contain no numeric literal but 0.
- *=make e2e= runs =npm install --prefer-offline=* at the root and in
  =e2e/= first, because the repo bind mount hides the image's
  =node_modules=. CI sets =HOME=/root= for Playwright's Firefox.

  =delete-video-files-removes-dash-and-original= and
  =deleting-a-video-closes-its-rooms=. No journey deletes a video (the
