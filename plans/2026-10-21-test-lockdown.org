* Goal
v0.4.x is working and stable. Two feature plans follow this one (autoplay on
load, room playlists) and both cut through the watch page, the websocket
protocol, the room model and the rooms table. Before they land, every
behaviour we rely on today gets a test that fails when it breaks. The audit
below says what is covered, what is not, and found two real bugs in
untested code plus one false assumption about the database. This plan adds
the missing tests, fixes the two bugs, and extracts one piece of client
logic into =sync_core.cljc= so the JVM suite can pin it. Nothing else
changes behaviour.

Baseline on =main= (2ea31c4): =make test= runs 56 tests, 116 assertions,
0 failures. The CLJS client has no tests at all and no test build.

** Bugs found in untested code
*** Login rate limit never fires
~src/clj/goob_toob/routes.clj:28-33~. Two independent faults:
- =(get @login-attempts [])= looks up the key =[]= (a literal empty
  vector), not =ip=. It is always nil, so =recent= is always empty and
  =ok?= is always true.
- The filter keeps attempts *older* than 60 s (=(> (- now %) 60000)=), the
  inverse of "recent".
Verified in the container: eight rapid =allow-login?= calls from one IP
return =[true true true true true true true true]= and the atom holds a
single timestamp. The admin UI's "too many tries, wait a minute" text
describes a limit that does not exist. Container mode exposes =/api/login=
on the public port, so this is the only brute-force defence and it is off.

*** One bad host command kills the beat loop for every room
~src/clj/goob_toob/services/sync.clj:111-118~ is a =future= running a bare
loop with no exception handling. ~ws.clj:29-30~ passes =(:pos m)= from the
JSON straight into =host-cmd!=, and ~sync.clj:61-64~ stores it unchecked.
A =cmd= with =pos= as a string (any co-host with the link, or an admin
typo in devtools) lands in =rooms*=; the next =tick-room!= calls
=sc/reanchor= / =expected-pos=, throws =ClassCastException=, and the
future ends. No room beats again until the process restarts, and the log
says nothing. The same lack of a =try= in the per-socket loop
(~ws.clj:64-71~) means a =status= with a non-numeric =pos= throws inside
=status!=, the go block dies, and ~ws.clj:73-75~ (=leave!=) never runs:
a ghost peer stays in the list forever.

** False assumption: foreign keys are not enforced
~src/clj/goob_toob/db.clj:47~ runs =PRAGMA foreign_keys=ON= once on the
datasource. That pragma is per connection, and next.jdbc opens a fresh
connection for every =execute!= on a datasource, so every real query runs
with foreign keys off. Verified in the container: =PRAGMA foreign_keys=
reads 0 on a fresh =execute!= and inside =with-transaction=, and an
=INSERT INTO rooms= with a bogus =video_id= is accepted. The code already
compensates by hand (~repos/room.clj:16-17~ checks the video exists,
~repos/video.clj:62~ deletes rooms before the video), which is why nothing
has broken. Not fixed here: flipping it on is a schema-touching change and
belongs to the playlist plan, which adds the next migration anyway. The
lockdown must not assert either way.

** Client logic worth pinning on the JVM
The start trigger in ~src/cljs/goob_toob/watch.cljs:281-303~ and the
unstarted branch of ~watch.cljs:98-101~ decide, from five booleans, whether
a viewer starts, starts the room, parks or does nothing. That table is the
exact thing the autoplay plan changes. It is pure; it just lives inside DOM
handlers. Extracting it to =sync_core.cljc= (as =policy= and =quality-cap=
already are) makes it testable here and lets the autoplay plan change one
function with a test table instead of a handler.

** What a real integration test needs
- JDK 11+ ships =java.net.http.HttpClient= with a WebSocket client, so a
  test can start Jetty on an ephemeral port with =routes/app=, log in over
  HTTP, pass the session cookie on the upgrade and drive =ws/endpoint= for
  real. No new dependency.
- The container image has ffmpeg 8.1 with libx264 (~container/Containerfile:7-10~),
  so the transcode pipeline can run end to end on a two-second =lavfi=
  clip inside =make test=. CI (~.github/workflows/ci.yml:9-33~) has no
  ffmpeg; it needs one =apt-get= line.
- =transcode/submit!= is a no-op while =control= is nil (~transcode.clj:160-162~),
  so route tests can upload without a worker.

#+begin_src clojure
(defn- ws-client
  "Opens a socket; returns {:ws ws :in chan}. Every complete text frame is
  parsed and put on :in."
  [port token nick cookie]
  (let [in (a/chan 64)
        buf (StringBuilder.)
        listener (reify java.net.http.WebSocket$Listener
                   (onOpen [_ ws] (.request ws 1))
                   (onText [_ ws data last?]
                     (.append buf data)
                     (when last?
                       (a/put! in (json/parse-string (str buf) true))
                       (.setLength buf 0))
                     (.request ws 1)
                     nil))
        b (cond-> (.newWebSocketBuilder (java.net.http.HttpClient/newHttpClient))
            cookie (.header "Cookie" cookie))
        ws (.join (.buildAsync b (java.net.URI. (str "ws://127.0.0.1:" port "/ws/room/" token "?nick=" nick)) listener))]
    {:ws ws :in in}))

(defn- send! [ws m] (.join (.sendText ws (json/generate-string m) true)))
(defn- recv! [in] (let [[v _] (a/alts!! [in (a/timeout 3000)])] v))
(defn- recv-type! [in t] (loop [] (when-let [m (recv! in)] (if (= t (:type m)) m (recur)))))

(defn start-action
  "What the watch page does with a start-related event. trigger is :play
  (the video element fired play) or :state (a room state arrived; also used
  on stream-ready and first pong). gesture? is navigator.userActivation.isActive
  at the :play. Returns :none, :park, :start or :start-room."
  [trigger {:keys [started? gesture? playing? can-control?]}]
  (cond
    (not= trigger :play) (if started? :none :park)
    started?             (if playing? :none :park)
    (not gesture?)       :park
    playing?             :start
    can-control?         :start-room
    :else                :park))
#+end_src

* Risks and open questions
- *The websocket test depends on Jetty's ring-websocket support* in
  =ring/ring 1.15.5=. =ws/endpoint= already runs on it in production, so the
  only unknown is port 0; Jetty honours it and =getURI= reports the bound
  port.
- *Timing in the ws tests.* Every receive has a 3 s timeout; "nothing
  arrives" assertions wait 500 ms to 1 s. The beat loop is not started in
  tests (=start-beat-loop!= is never called), so the only traffic is what
  the test sends.
- *Real ffmpeg in CI* adds about 30 s of apt time per run. Accepted; it is
  the one test that would have caught #1 and #3.
- *The rate-limit fix changes behaviour* on the public port: five wrong
  passwords in a minute now lock that IP for the remainder of the minute.
  That is what the UI already claims.
- *Foreign keys stay off* until the playlist plan. No test in this plan
  asserts enforcement either way.
- *created_at resolution* is one second; =list-all-is-newest-first= sleeps
  1.1 s. Alternative: insert with explicit =created_at= via a direct
  =jdbc/execute!= in the test. Implementer's choice; say which.

* Implementation notes
Implemented 2026-10-21 by three Opus subagents from this plan (steps 1-2,
3-4, 5-7), reviewed and verified by the planning session; PR for #35.
Landed as specced, plus:

- *Step 7 was wrong about one row.* Today a first play with a gesture into
  a paused room without control sets =started= *and then* parks, so the
  host's next play starts that viewer. Dispatching only on
  =start-action='s =:park= would have left them unjoined. The handler
  therefore keeps "joined" (gesture on an unstarted viewer) separate from
  "what the video does" (the =start-action= result); the function and its
  table are as written. The autoplay plan carries this split.
- *Stream-ready and first-pong parks* are not routed through
  =start-action=; they park unconditionally today and routing them would
  have changed behaviour. The autoplay plan's =settle!= is where they go.
- *=run-ffmpeg= had a race*: the stderr string was built right after
  =.waitFor= without waiting for the reader thread. Fixed by joining the
  =a/thread= channel first (own commit).
- *Fake ffmpeg exit code* is baked into the script at creation; the JVM
  cannot set an env var for a child without a production change.
- *Assertions the audit could not make fail* were replaced, not kept: the
  =list-all=-based room check (inner join hides orphans; =get-by-id= used),
  the "after recovery =:slow-for nil=" check (=room-rate= already returns
  nil; a host pause while slowed is asserted instead), the "beat keeps
  arriving" check on string positions (the beat never touched =pos=; the
  state message is asserted). One redundant stamp assertion was merged.
- *Joint coverage*: =a-malformed-status-does-not-ghost-the-peer= fails only
  when both the =num= coercion and the socket =try= are removed, so
  =a-non-object-frame-does-not-kill-the-socket= was added to pin the =try=
  alone.
- *Verified*: =make test= 128 tests, every new test audited to fail under
  a production break (tables in the PR); =make compile= with the same four
  =admin.cljs= inference warnings before and after; the 429 checked over
  HTTP against the running container.
